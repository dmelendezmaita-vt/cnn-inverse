# Restore Runbook

This runbook is restore-focused operational documentation for:

- `tools/restore_project.sh`

Use it when recovering code/config state from a previously created backup archive.

## 1. Purpose and When To Use Restore

Run restore when you need to:

- revert project code/config to a known-good snapshot
- recover from accidental edits
- reproduce a prior experiment configuration baseline

Restore is designed to overwrite included backup paths only. It does not delete unrelated files in the target directory.

## 2. Pre-Restore Checklist

Before restoring:

1. Verify archive path:
   - Confirm `--archive` points to intended backup.
2. Verify target path:
   - Confirm `--target` is the project directory you want to overwrite.
3. Verify integrity:
   - Ensure both `<archive>.sha256` and `<archive>.files.sha256` exist and validate.
4. Estimate impact:
   - Restore may replace active working files; coordinate with collaborators if needed.

## 3. Safety Model

`--backup-current` controls how current target state is preserved:

- `prompt` (default): ask user whether to create pre-restore backup.
- `always`: always create pre-restore backup automatically.
- `never`: skip pre-restore backup.

If pre-restore backup is not created, script requires explicit overwrite confirmation (unless `--yes` is provided).

Pre-restore backup naming:

- Prefix: `fhn_dnn_pre_restore`
- Destination default: `/projects/neuro-collab/archives/fhn_dnn`
- Timestamp format: `YYYYmmdd_HHMMSS`
- Backup scope for pre-restore snapshots: `repo` (relative to `--target`)
- Implication: pre-restore backup no longer depends on the `--scope key` allowlist (for example, optional files like `DMM research progress.pdf` are not required)

## 4. Step-by-Step Restore Procedures

## A. Interactive safe restore (recommended)

```bash
cd /projects/neuro-collab/code/fhn_dnn-1-implementation-in-pytorch
bash tools/restore_project.sh \
  --archive /projects/neuro-collab/archives/fhn_dnn/fhn_dnn_backup_YYYYmmdd_HHMMSS.tar
```

Expected flow:

1. Archive existence check.
2. Archive checksum validation (`.sha256`).
3. Staging extraction and staged-file checksum validation (`.files.sha256`).
4. Prompt to create pre-restore backup.
5. Restore into target directory.
6. Post-restore checksum validation on target (`.files.sha256`).

## B. Non-interactive restore

```bash
bash tools/restore_project.sh \
  --archive /projects/neuro-collab/archives/fhn_dnn/fhn_dnn_backup_YYYYmmdd_HHMMSS.tar \
  --backup-current always \
  --yes
```

Use for automation where prompts are not possible.

## C. Dry-run validation

```bash
bash tools/restore_project.sh \
  --archive /projects/neuro-collab/archives/fhn_dnn/fhn_dnn_backup_YYYYmmdd_HHMMSS.tar \
  --dry-run
```

Dry-run validates inputs and checksum logic (including temporary staging extraction/checks), then prints planned actions without modifying the target path.

## 5. Confirmation Prompt Examples

Prompt mode backup decision:

```text
Create pre-restore backup of current target before restoring? [Y/n]:
```

If user declines pre-restore backup:

```text
No pre-restore backup selected. Type OVERWRITE to continue:
```

`OVERWRITE` must be typed exactly to proceed.

## 6. Rollback Procedure

If restore result is not desired:

1. Identify pre-restore archive generated by restore script:
   - `/projects/neuro-collab/archives/fhn_dnn/fhn_dnn_pre_restore_YYYYmmdd_HHMMSS.tar`
2. Run restore again using that archive:

```bash
bash tools/restore_project.sh \
  --archive /projects/neuro-collab/archives/fhn_dnn/fhn_dnn_pre_restore_YYYYmmdd_HHMMSS.tar \
  --backup-current always
```

This returns project files to the pre-restore state snapshot.

## 7. Integrity Validation

Verify archive checksum:

```bash
cd /projects/neuro-collab/archives/fhn_dnn
sha256sum -c fhn_dnn_backup_YYYYmmdd_HHMMSS.tar.sha256
```

Verify restored files checksum from target root:

```bash
cd /projects/neuro-collab
sha256sum -c /projects/neuro-collab/archives/fhn_dnn/fhn_dnn_backup_YYYYmmdd_HHMMSS.tar.files.sha256
```

Inspect archive contents:

```bash
tar -tf /projects/neuro-collab/archives/fhn_dnn/fhn_dnn_backup_YYYYmmdd_HHMMSS.tar | less
```

Check manifest metadata:

```bash
cat /projects/neuro-collab/archives/fhn_dnn/fhn_dnn_backup_YYYYmmdd_HHMMSS.tar.manifest.txt
```

Inspect exact file list in backup:

```bash
cat /projects/neuro-collab/archives/fhn_dnn/fhn_dnn_backup_YYYYmmdd_HHMMSS.tar.filelist.txt
```

## 8. Failure Modes and Troubleshooting

Checksum mismatch:

- Symptom: restore aborts during checksum validation.
- Action: do not proceed; obtain valid archive/sidecar pair.

Archive missing:

- Symptom: `Archive not found` error.
- Action: verify path and filename.

Permission errors:

- Symptom: cannot read archive or write pre-backup/target.
- Action: verify permissions or use writable destination paths.

Prompt failure in non-TTY context:

- Symptom: script errors in interactive prompt when no terminal is attached.
- Action: use `--yes` and an explicit `--backup-current` mode.

Partial extraction concerns:

- Action: re-run restore from a known-good archive after validating checksum.
- If needed, recover from pre-restore backup archive generated before the failed attempt.

## 9. Operational Conventions

Retention guidance:

- Keep daily backups for short-term recovery.
- Keep milestone backups for major experiment changes.
- Prune stale backups periodically.

Naming conventions:

- regular backups: `fhn_dnn_backup_YYYYmmdd_HHMMSS.tar`
- pre-restore backups: `fhn_dnn_pre_restore_YYYYmmdd_HHMMSS.tar`

Important note on data archives:

- Large dataset archives under `/projects/neuro-collab/data/tar_files` are not included in default key-scope backups.
- Preserve dataset tarball paths and checksums separately when documenting a full experiment state.
